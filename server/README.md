# Shared Albums – Backend

שרת לאתר האלבומים השיתופיים: Node.js, Express ו-TypeScript, מסד נתונים PostgreSQL דרך Prisma, ואחסון תמונות ב-Cloudinary.

> להעלאה ראשונה לאינטרנט, צעד אחרי צעד: **START-HERE.md**
> לכתיבת צד ה-React מול השרת: **FRONTEND-API-GUIDE.md**
> כל ה-Endpoints עם דוגמאות: **Swagger** בכתובת `/api-docs`

## מבנה הפרויקט

```
src/
  server.ts              נקודת הכניסה: טוען .env, מתחבר למסד ומפעיל את השרת
  app.ts                 הרכבת Express: CORS, JSON, נתיבים, Swagger, שגיאות
  config/env.ts          בדיקת משתני הסביבה (Zod)
  db/prisma.ts           החיבור למסד הנתונים
  routes/                אילו כתובות קיימות ואיזה controller מטפל בכל אחת
  controllers/           קריאת הבקשה, ולידציה, קריאה ל-service והחזרת תשובה
  services/              הלוגיקה: אלבומים, תמונות, הרשאות, התחברות, Cloudinary
  schemas/               סכמות Zod לולידציה של כל קלט
  middleware/            אימות טוקן, העלאת קבצים, טיפול בשגיאות
  utils/                 שגיאות HTTP, עטיפת async, המשתמש המחובר
  docs/swagger.ts        Swagger UI ו-openapi.json
  types/express.ts       req.user
prisma/
  schema.prisma          מבנה הטבלאות
  migrations/            יצירת הטבלאות במסד (SQL)
  seed.ts                נתוני הדגמה
tests/                   בדיקות אוטומטיות (Vitest + Supertest)
docs/openapi.json        תיעוד ה-API בפורמט OpenAPI 3
render.yaml              הגדרות פריסה ל-Render
```

## הרצה מקומית

```bash
npm install          # מתקין תלויות ויוצר את Prisma Client
cp .env.example .env # ואז למלא את הערכים בקובץ .env
npm run db:migrate   # יוצר את הטבלאות במסד
npm run db:seed      # אופציונלי: נתוני הדגמה (דורש SEED_PASSWORD)
npm run dev          # השרת רץ על http://localhost:4000
```

פתחי בדפדפן:
- `http://localhost:4000/api/health` – אמור להחזיר `{"ok":true}`
- `http://localhost:4000/api-docs` – Swagger

## מסד הנתונים

| טבלה | מה יש בה |
|---|---|
| `User` | משתמשים. הסיסמה נשמרת כ-hash של bcrypt |
| `Album` | אלבומים: שם, תיאור, תאריך, קטגוריה, הרשאת העלאה, הרשאת הורדה, מנהל, וקוד קישור ההצטרפות |
| `Participant` | משתתפים בכל אלבום: המנהל, אורחים שהצטרפו דרך הקישור עם שם לתצוגה, ומשתמשים רשומים שהצטרפו דרך הקישור |
| `Photo` | תמונות: כתובת ב-Cloudinary, SHA-256 של התוכן, איזה משתתף העלה |
| `PhotoLike` | לייקים: תמונה + משתתף, אחד לכל זוג |

קשרים: לכל משתמש הרבה אלבומים, לכל אלבום הרבה משתתפים ותמונות, ולייק מחבר תמונה למשתתף. מחיקת אלבום מוחקת את המשתתפים, התמונות והלייקים שלו. משתתף שהוסר מסומן ב-`removedAt`: הגישה שלו נחסמת, והתמונות שלו נשארות.

## הצטרפות והרשאות

- **משתמש רשום** נרשם ומתחבר עם מייל וסיסמה, ופותח אלבומים.
- לכל אלבום יש **קישור הצטרפות** (`/join/<joinCode>`). מי שפותח אותו כותב שם לתצוגה, ומקבל **טוקן משתתף** שעובד רק באלבום הזה. אין הרשמה ואין סיסמה.
- משתמש שמחובר לחשבון ונכנס דרך הקישור מצטרף עם החשבון, והאלבום מופיע אצלו ב"אלבומים ששותפו איתי".
- המנהל יכול ליצור קישור חדש (הישן מפסיק לעבוד), לראות את רשימת המשתתפים ולהסיר משתתף.
- המנהל שולט בהעלאות ובהורדות: `allowUpload: false` עוצר העלאות של משתתפים (המנהל תמיד יכול להעלות), ו-`allowDownload: false` עוצר הורדות של משתתפים (הם מקבלים רק גרסת צפייה מוקטנת).

| פעולה | משתתף | מנהל אלבום |
|---|---|---|
| צפייה באלבום ובתמונות | כן | כן |
| העלאה | רק כש-allowUpload פעיל | כן |
| לייק וביטול לייק | כן | כן |
| עריכת אלבום והרשאות העלאה והורדה | לא | כן |
| קישור חדש, רשימת משתתפים, הסרת משתתף | לא | כן |
| הורדת תמונה מלאה | רק כש-allowDownload פעיל | כן |
| מחיקת תמונה או אלבום | לא | כן |

מי שאינו מנהל ואינו משתתף מקבל 403 על כל פעולה באלבום. בלי טוקן תקין: 401. טוקן משתתף לא מתקבל בנתיבים של משתמש רשום (האלבומים שלי, יצירה, עריכה, ניהול): 401.

## מה לדעת להסביר על השרת

- **לאיזה API ה-React פונה:** לכתובות שמתחילות ב-`/api`, לפי הטבלה ב-FRONTEND-API-GUIDE.md.
- **מה נשלח ומה חוזר:** JSON, חוץ מהעלאת תמונות שנשלחת כ-FormData. שגיאה חוזרת כ-`{ "error": "..." }`.
- **איך נשמר המידע:** ב-PostgreSQL, דרך Prisma. קבצי התמונות ב-Cloudinary, ובמסד רק הכתובת.
- **איך עובדת ההתחברות:** הסיסמה נשמרת כ-hash. בהתחברות השרת מחזיר JWT חתום, והלקוח שולח אותו בכל בקשה בכותרת `Authorization: Bearer`. אורח שהצטרף דרך קישור מקבל JWT מסוג אחר (טוקן משתתף), שמזהה אותו רק באלבום אחד (`src/utils/tokens.ts`).
- **איך עובדות ההרשאות:** השרת מזהה את מבצע הבקשה לפי הטוקן בלבד, ובודק בכל בקשה אם הוא המנהל או משתתף פעיל באלבום (`src/services/access.service.ts`).
- **למה קישור הצטרפות:** המשתתפים באירוע לא צריכים להירשם. השליטה נשארת אצל המנהל: הסרת משתתף, קישור חדש, נעילת העלאות ומחיקת תמונות.
- **איך נמנעות כפולות:** לכל קובץ מחושב SHA-256. השרת בודק אותו מול האלבום לפני השמירה, ובמסד יש אילוץ ייחודיות על אלבום + hash.
